### 4.1 版本时间线总览

- mermaid 或表格一行：2017 MVP/1.0 → 2022 规范共识 / 2024-12 W3C 正式 2.0 → 2025-09 发布 3.0
- 主来源：
  - [Wasm 2.0 Completed](https://webassembly.org/news/2025-03-20-wasm-2.0/)
  - [Wasm 3.0 Completed](https://webassembly.org/news/2025-09-17-wasm-3.0/)
  - [Change History](https://webassembly.github.io/spec/core/appendix/changes.html)
  - [Feature Status](https://webassembly.org/features/)

### 4.2 Wasm 1.0（MVP）：基线能力

要点（与前三章呼应，不重复深挖）：

- 栈式 VM、模块/实例、12 种标准段、172 条指令、4 种数值类型、单线性内存、无 GC / 无原生异常 / 无 SIMD
- **浏览器基线支持**（共识四引擎）：


| 引擎                       | 大致起始版本              | 时间      |
| ------------------------ | ------------------- | ------- |
| Chrome / Edge (Chromium) | Chrome 57 / Edge 16 | 2017    |
| Firefox                  | 52                  | 2017-03 |
| Safari                   | 11                  | 2017-09 |


### 4.3 Wasm 2.0：算力与引用类型升级

按官方变更清单归纳（不抄 §3.2 长表，按版本打包写「为什么重要」）：

- Sign-extension / Non-trapping float-to-int
- Multi-value（多返回值 + block 参数）
- Reference Types（`funcref` / `externref`）+ 多表 + table 指令
- Bulk Memory（含 datacount 段）
- Fixed-width SIMD（`v128`，大量向量指令）

浏览器支持用**「该版本能力齐套所需的大致版本」**表述，并注明各特性落地略有先后；矩阵列 Chrome / Firefox / Safari（Edge 随 Chromium）。数据以 [webassembly.org/features](https://webassembly.org/features/) 为准核对；文中可沿用 §3.2 已有 Chrome 数字作为交叉索引。

参考量级（撰写时再最终核对，计划中先占位）：

- Multi-value / BigInt i64：Chrome ~85、Firefox ~78、Safari ~14.1
- Bulk Memory：Chrome ~75、Firefox ~79、Safari ~15
- SIMD：Chrome ~91、Firefox ~89、Safari ~16.4
- Reference Types：Chrome ~96、Firefox ~79、Safari ~15

### 4.4 Wasm 3.0：托管语言与大型应用基建

对应 [官方公告](https://webassembly.org/news/2025-09-17-wasm-3.0/) 的核心条目：

- Memory64（i64 寻址；Web 侧仍有上限）
- Multiple Memories（单模块多线性内存）
- Garbage Collection（struct/array 堆类型，低层 GC，非完整对象系统）
- Typed References / `call_ref`（与 GC 联动）
- Tail Calls
- Exception Handling（exnref 最终模型；可简提 Legacy EH 已被取代）
- Relaxed SIMD + Deterministic profile
- 文本格式 Custom Annotations
- JS 嵌入相关：JS String Builtins（可一句带过 JSPI 等非 core 但仍热门的扩展，避免喧宾夺主）

浏览器矩阵：标出 3.0「头牌」特性（GC / Exception / Memory64 / Multi-memory / Tail call）在 Chrome / Firefox / Safari 的起始或「尚未齐套」状态。可说明：**3.0 已是 live 标准，但 Safari 对 Memory64 / Multi-memory / Relaxed SIMD 等仍可能落后**——与 UNO「State of Wasm 2025–2026」及 feature 页一致；避免写成「所有浏览器已完整实现 3.0」。

### 4.5 读版本时的实用提醒

短节即可：

- 规范版本 ≠ 一次全部浏览器齐套；生产用 `[wasm-feature-detect](https://github.com/GoogleChromeLabs/wasm-feature-detect)` 按特性探测
- Threads（shared memory）**不在** 2.0/3.0 core 总述的同一叙事里重点展开（它是长期提案 + COOP/COEP），一句指回 §3.5/平台限制即可
- Component Model / WASI 是生态层，**不属于** core 1.0→3.0 版本线——指到第 3 章 WASI 与后文章节

3–5 句：1.0 算力基线 → 2.0 SIMD/引用/批量内存 → 3.0 GC/异常/大寻址；下一章（新第 5 章）进入浏览器加载与 Rust 裸编译实战。
